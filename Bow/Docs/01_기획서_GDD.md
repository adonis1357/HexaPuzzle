## 1. 게임 컨셉

### 1.1 한 줄 정의 & Core Fantasy (3줄)
실시간 1:1 궁수 대전. 바람 부는 들판에서 마주 선 두 궁수가 각도·힘·추 타이밍을 맞춰 먼저 상대를 쓰러뜨린다.

1. **바람을 읽는 명사수** — 매 순간 변하는 바람을 눈으로 읽고, 감으로 보정해서 맞히는 쾌감 (조준 가이드는 바람을 보여주지 않는다).
2. **숨을 고르는 자의 한 방** — 쏘고 나서 서두르지 않고 호흡을 고르면(최적 10초) 다음 화살이 1.5초 만에 나간다. 인내가 곧 템포 무기.
3. **먹과 한지 위의 결투** — 국궁 실루엣과 먹선 바람, 금박 Perfect가 만드는 짧고 선명한 한 판.

### 1.2 타겟 & 세션
| 항목 | 내용 |
|------|------|
| 주 타겟 | 15~35세 모바일 캐주얼~미드코어. 드래그-발사형(앵그리버드류) 조작에 익숙하고 짧은 대인전을 선호하는 층 |
| 플레이 환경 | 모바일 세로 1080×1920, 한 손(엄지) 조작. 에디터에서는 마우스 |
| 1판 길이 | 최대 120s + 카운트다운 3s + 결과 ~10s = **약 2분 15초** (KO 시 더 짧음. 중앙값 목표 80~100s) |
| 1세션 | 3~5판 연속 (재대결 버튼으로 로비 복귀 없이 즉시 재시작) |
| 학습 난이도 | 첫 판에서 드래그→추→탭 3단계 이해(봇 Easy), 5판 내 바람 보정 체감, 20판 내 호흡 리듬 체득이 목표 |

## 2. 코어 루프 & 상태 흐름

### 2.1 매치 단위 흐름
```
[로비] ──(봇 대전 / LAN 호스트 / LAN 참가)──▶ [매치 설정 동기화]
   ▲                                              seed·사거리·높이차 확정
   │                                                     ▼
[결과] ◀──(KO / 시간 종료 / 항복·접속 끊김)── [PLAY 120s] ◀── [카운트다운 3-2-1]
   │  승·패·무, 명중률, Perfect 수, 최장 호흡                    (입력 잠금, 바람은 이미 흐름)
   └──▶ 재대결(같은 상대, 새 seed) / 로비
```
| 상태 | 진입 조건 | 종료 조건 | 비고 |
|------|----------|----------|------|
| Lobby | 앱 시작/결과에서 복귀 | 모드 선택 | 봇 난이도(3단계) 선택 |
| Sync | 모드 선택 | 설정 수신(네트워크) 또는 즉시(봇) | seed, 사거리 16~24 m, 높이차 ±1.5 m, 선후 위치 |
| Countdown | Sync 완료 | 3→2→1→"쏴라!" (총 3.0s) | 경기시간 t=0은 "쏴라!" 시점. 바람 HUD는 카운트 중 미리 표시(연습 가능) |
| Playing | t=0 | HP 0 또는 t=120s | 양측 동시에 장전 5.0s로 시작(★ §5.2) |
| Resolving | 시간 종료 시 비행 중 화살 존재 | 모든 화살 착탄 또는 최대 3.0s | 신규 발사 불가, 착탄 데미지는 유효 |
| Result | KO 확정 또는 Resolving 종료 | 사용자 선택 | 봇 모드는 일시정지 가능, 네트워크 모드는 불가 |

### 2.2 궁수 1인의 사격 사이클 (핵심 루프)
```
 ┌─ Reload(D) ─▶ Ready(호흡 h 누적) ─▶ Aim(드래그) ─▶ Pendulum(추, ≤3s) ─▶ Fire ─┐
 │   장전 링 감소      금색 호흡 링 증가      각도·힘 결정      오차 p 결정        화살 비행 │
 └────────────────────  D_next = 5×(1−0.7·E(h))  ◀──────────────────────────────────┘
```
| 상태 | 허용 입력 | 규칙 |
|------|----------|------|
| Reload | 드래그(**사전 조준**) 허용 | 손을 떼도 추는 시작하지 않고 "대기 조준" 유지. Reload 종료 순간 대기 조준이 있으면 즉시 추 시작 |
| Ready | 드래그 | h = 장전 완료 후 경과 시간. 드래그 유지 중에도 h는 계속 누적(★) |
| Aim | 드래그 유지 | 40 px 미만으로 되돌려 손을 떼면 **조준 취소**(Ready 복귀, h 유지) |
| Pendulum | 탭 | 탭 = 발사. 3.0s 경과 시 자동 발사 |
| Fire | 없음 | 발사 시각 t_f 기록, h 확정 → D_next 계산 → Reload |

★ 핵심 의도: 플레이어는 "언제 쏠지"를 매 순간 선택한다. 서두르면 바로 쏘고(5s 주기), 참으면 다음 발을 앞당긴다. 이동/회피가 없으므로 모든 선택은 **조준 품질 + 발사 타이밍**에 집중된다.

## 3. 조준 입력 상세

### 3.1 3단계 요약
1. **드래그**: 화면 아무 곳에서 터치 시작 → 당긴 방향의 반대로 조준. 각도 = 방향, 힘 = 길이.
2. **추 미터**: 손을 떼면 시작. 좌↔우 왕복, 오프셋 p ∈ [−1, 1].
3. **탭**: 발사. 각도 오차 = p × 6°. |p| < 0.08 → **Perfect**.

### 3.2 드래그 → 각도/힘 매핑
- 앵커 = 터치 시작점. 드래그 벡터 d = 현재점 − 앵커. 조준 벡터 a = −d.
- **각도** θ_aim = atan2(a_y, a_x) (우향 기준, +는 위). 클램프 **−10° ~ +85°**, 0.25° 단위 양자화. 후방(좌향) 조준 불가: a_x ≤ 0이면 가장 가까운 한계각으로 고정.
- **힘** f = clamp((|d| − 40) / 320, 0, 1). 데드존 40 px(조준 시작·취소 판정), 최대 360 px.
- **앵커 추종**: |d| > 360 px이면 앵커가 손가락 쪽으로 끌려와 길이를 360 px로 유지(손가락이 화면 끝에 막히지 않음).

| 드래그 길이 (px) | 40 | 80 | 120 | 160 | 200 | 240 | 280 | 320 | 360 |
|---|---|---|---|---|---|---|---|---|---|
| 힘 f | 0 | 0.125 | 0.250 | 0.375 | 0.500 | 0.625 | 0.750 | 0.875 | 1.000 |
| 초속 v = 9+13f (m/s) | 9.00 | 10.63 | 12.25 | 13.88 | 15.50 | 17.13 | 18.75 | 20.38 | 22.00 |

- 정밀도: 1 px = f 0.003125 = 0.041 m/s. 사거리 20 m·45° 기준 **1 px ≈ 0.12 m**. 모바일 손가락 오차(±3 px)는 ±0.35 m → 몸통(§6)보다 작아 허용 가능.
- 드래그 중 HUD: 각도(°)·힘(%) 숫자를 손가락 **위쪽**(엄지에 가리지 않는 곳)에 표시.
- 조준 가이드(확정): 바람 무시, **초기 0.5s 궤적만 점 3개**(0.17s 간격). 거리 예측용 눈금은 주지 않는다.

### 3.3 정확도 추(錘) 미터
| 항목 | 사양 |
|------|------|
| 파형 | p(t) = sin(2π·t / T_p + φ0), **시작 위상 φ0 = π/2** (p = ±1 끝점에서 시작 — 즉시 탭해도 중앙이 아님) |
| 주기 | T_p = 1.1 × (1 + 0.3·E) s. E는 **추 시작 시점 h**로 계산해 추 동작 중 고정. 범위 1.10 s(E=0) ~ 1.43 s(E=1) |
| 오차 적용 | 최종 발사각 θ = θ_aim + 6° × p (p>0은 위로). 최대 ±6° |
| Perfect | \|p\| < 0.08 (오차 ≤ 0.48°). 판정 창: 중앙 통과 속도 기준 **약 28 ms (E=0) ~ 36 ms (E=1)**. 무작위 탭 시 Perfect 확률 5.1% |
| 입력 유예 | 추 시작 후 **0.15 s 동안 탭 무시**(드래그 해제 직후 오탭 방지). 끝점 시작이므로 첫 중앙 통과는 0.275 s(E=0) |
| 자동 발사 | 추 시작 3.0 s 후 **현재 p로 자동 발사**. 자동 발사는 Perfect 불가(★ 타임아웃 위상 악용 방지). 2.0 s부터 링 점멸, 2.6 s부터 진동 |
| 시각 피드백 | 추 막대 + 중앙 금색 눈금. Perfect 시 금색 번쩍 + 햅틱 강, 일반 시 약. 판정 문구 "完" (Perfect) |
| 호흡 연동 | E가 클수록 추가 느려지고(위 주기) 같은 탭 시차에 대한 \|p\| 변화도 작아짐 → 호흡의 직접 보상 |

### 3.4 모바일 한 손 UX 고려사항
1. **엄지 도달 영역**: 드래그 시작 가능 영역은 화면 전체(상단 HUD 12% 제외). 앵커가 터치 시작점이라 어느 위치든 조작 가능, 왼손/오른손 구분 불필요.
2. **가림 방지**: 엄지가 가리는 하단~우측에 중요 정보를 두지 않는다. 바람·호흡·HP·타이머는 상단, 궁수·표적·궤적은 화면 중단 이상.
3. **한 손가락 연속 동작**: 드래그→뗌→탭이 같은 엄지로 이어지도록, 탭은 **화면 아무 곳**(버튼 아님)을 허용한다.
4. **멀티터치**: 첫 터치만 유효. 두 번째 터치는 무시(손바닥 오터치 방지).
5. **취소 수단**: 드래그를 40 px 안쪽으로 되돌려 떼면 취소(실수 방지). 추 시작 후에는 취소 불가.
6. **햅틱**: 힘 0.25 단계마다 약한 틱, 장전 완료 시 틱, 호흡 정점(10 s) 도달 시 미세 진동, Perfect 시 강진동.
7. **입력 지연 보정**: 탭 판정은 터치 이벤트 타임스탬프 기준(프레임 시작 시각이 아님)으로 p를 계산한다.
8. **앱 이탈**: 봇 모드는 자동 일시정지, 네트워크 모드는 10 s 이내 복귀 못 하면 기권 처리(§8.4).
9. 최소 터치 타깃 48 dp (결과/로비 버튼). 인게임은 타깃 없음.

## 4. 탄도 & 바람

### 4.1 공식 (확정)
| 항목 | 식 |
|------|----|
| 초속 | v = 9 + 13·f (9~22 m/s) |
| 발사각 | θ = θ_aim + 6°·p |
| 초기 속도 | vx0 = v·cosθ, vy0 = v·sinθ |
| 가속도 | a_y = −9.81 m/s², **a_x = 0.6 × w(t)** (t = 해당 순간의 경기시간) |
| 바람 | w(t) = 4·sin(2πt/23 + φ1) + 2·sin(2πt/7 + φ2) + 1·sin(2πt/2.3 + φ3), φ_i = hash(seed, i)·2π. 범위 ≈ ±7 m/s (+ = 오른쪽) |
| 적분 | 고정 스텝 dt = 1/120 s, 세미 임플리싯 오일러(vx, vy 갱신 후 위치 갱신). 바람은 **화살이 날고 있는 그 순간의 경기시간**으로 평가(발사 시점 값 고정 아님) |
| 종료 | 몸/머리 충돌, 지면(y ≤ ground(x)) 또는 비행 6.0 s 초과 시 소멸. 지면은 두 궁수 발밑 높이를 선형 보간, 표적 뒤쪽은 표적 높이 유지 |

- 플레이어(왼쪽)는 오른쪽 바람이 순풍(사거리 증가), 왼쪽 바람이 역풍. 네트워크의 상대 화면은 좌우 반전되어도 **w의 부호는 월드 좌표 기준 동일**하게 계산하고 렌더링 때만 뒤집는다.
- 바람 통계(시드 200개 × 120 s 시뮬레이션): \|w\| 중앙값 2.6 m/s, 90백분위 5.2 m/s, 최대 7.0 m/s. **\|w\| < 1.5 m/s인 "고요 창"이 시간의 약 29%**, < 3 m/s는 58%. → 고요 창을 기다려 쏘는 전술이 성립(호흡 시스템과 시너지).

### 4.2 예시 계산 — 거리 20 m, 각도 45°, 힘 0.6 (v = 16.8 m/s)
근사: T = 2·v·sinθ/g, 낙점 x = v·cosθ·T + ½·(0.6w)·T² (발사 높이와 같은 높이 도달 기준, 풍속은 비행 중 상수 가정)

| 바람 w (m/s) | a_x (m/s²) | 비행시간 T (s) | 무풍 사거리 (m) | 바람 이동 (m) | 낙점 x (m) | 20 m 대비 |
|---|---|---|---|---|---|---|
| 0 | 0.0 | 2.42 | 28.77 | 0.00 | 28.77 | **+8.77 (오버)** |
| +4 | +2.4 | 2.42 | 28.77 | +7.04 | 35.81 | **+15.81 (오버)** |
| −6 | −3.6 | 2.42 | 28.77 | −10.56 | 18.21 | **−1.79 (살짝 미달)** |

해석: 같은 입력이라도 바람만으로 낙점이 18.2 m ↔ 35.8 m로 **17.6 m 흔들린다**. 바람 보정은 선택이 아니라 게임의 본질이다.

**동일 조건에서 20 m에 맞추려면 필요한 힘 (45° 고정)**
| 바람 w | 0 | +4 | −6 |
|---|---|---|---|
| 필요 힘 f | 0.385 (v 14.01) | 0.273 (v 12.56) | 0.662 (v 17.61) |
| 드래그 길이 | 163 px | 127 px | 252 px |

**각도별 비교 (거리 20 m, 무풍 기준으로 맞춘 샷)**
| 각도 | 필요 힘 | 비행 T (s) | 바람 1 m/s당 낙점 이동 (m) | 추 오차 6°의 상하 편차 (m) | 풍속 6 m/s 시 이동 (m) |
|---|---|---|---|---|---|
| 20° | 0.652 | 1.22 | 0.45 | ±1.8 (0.30 m/°) | 2.7 |
| 30° | 0.466 | 1.53 | 0.71 | ±1.4 (0.23 m/°) | 4.2 |
| 45° | 0.385 | 2.02 | 1.22 | ≈ 0 (1차 효과 0) | 7.3 |
| 60° | 0.466 | 2.66 | 2.12 | ±4.2 (0.70 m/°) | 12.7 |

→ **낮은 각도 = 바람에 강하고 추 오차에 약함, 높은 각도 = 반대.** 45°는 추 오차에 면역이지만 바람에 가장 민감. 이 대립이 "각도 선택"의 전술 깊이이며 의도된 설계다. 참고: 사거리 16~24 m를 커버하는 필요 힘 범위는 20°에서 0.51~0.78, 30°에서 0.34~0.58, 45°에서 0.27~0.49.

## 5. ★ 호흡(Breath) 딜레이 시스템

### 5.1 정의 (확정)
- 기본 딜레이 B = 5.0 s. 장전 완료 시각 t_r = t_f + D_현재.
- 초과 대기 h = (다음 발사 시각) − t_r ≥ 0.
- 호흡 효율 **E(h) = (h/P)·e^(1−h/P)**, P = 10 s. (E(10)=1, 이후 감소)
- 다음 딜레이 **D_next = 5 × (1 − 0.7·E(h))** → 최소 1.5 s.
- 추 주기 T_p = 1.1 × (1 + 0.3·E).
- 적용 순서: 발사 N의 h → 발사 N 직후의 딜레이 D_N 결정. 즉 "참고 쏜 그 발" 뒤의 장전이 짧아진다.

### 5.2 규칙 상세
1. 매치 시작(t=0) 시 양측 모두 D = 5.0 s 장전(첫 발 최소 t=5.0 s, 공정성). h는 t=5.0 s부터 누적.
2. h에는 드래그 유지 시간과 추 시간이 **모두 포함**(조준하느라 쓴 시간도 호흡으로 인정).
3. E 계산은 호스트/봇 포함 동일 함수. 부동소수 오차 방지를 위해 h를 ms 정수로 반올림해 계산.
4. 기권/일시정지 중 시간은 경기시계가 멈춘 구간만큼 제외(봇 모드).

### 5.4 플레이 리듬 분석
| 패턴 | 설명 | 평균 발사 간격 | 분당 발수 |
|------|------|---------------|----------|
| A. 속사형 | 장전 끝나자마자 계속 발사 (h≈0) | 5.00 s | 12.0 |
| B. 단발 숙고형 | 매번 h=5 | 7.11 s | 8.4 |
| C. 정점 호흡형 | 매번 h=10 | 11.50 s | 5.2 |
| D. **버스트형** | h=10에서 한 발 → 1.5 s 뒤 즉시 한 발(h=0) → 5 s 장전 → 반복 | 16.5 s / 2발 = 8.25 s | 7.3 |
| E. 고요 창 대기형 | h=2~8 사이 바람이 \|w\|<1.5가 될 때 발사 | 5.4~9.6 s | 6~11 |

- ★ **"10초 대기 → 1.5초 속사"**: 첫 발을 h=10에 쏘면 1.5 s 뒤 두 번째 발이 나간다. 화살 비행시간(1.2~2.7 s)이 1.5 s와 비슷하므로 두 번째 발은 첫 발의 착탄을 **일부만 보고 보정**할 수 있다(낮은 각도일수록 유리). 핵심 가치는 관측 사격 + 상대가 반응하기 전에 두 발이 연달아 도달하는 **템포 압박**이다.
- **솔직한 분석(밸런스 최대 리스크)**: 순수 발사 수로는 패턴 A가 모든 대기형보다 빠르다 (D_next 감소량이 대기 시간보다 항상 작음; 정상 상태 간격 T(h) = 5(1−0.7E(h)) + h는 h=0에서 최소 5.0 s). 버스트형 D는 속사형 대비 **발사 수 -39%** (8.25 s vs 5 s)이므로, 호흡은 "더 많이 쏘는" 수단이 아니라 **"한 발의 품질·타이밍을 사는" 수단**이어야 한다. 현재 호흡 보상은 ① 추 주기 +30%(Perfect 창 28→36 ms), ② 고요 창 대기, ③ 버스트 템포뿐이므로, 대기형이 속사형을 이기려면 명중률이 약 1.4~1.65배 높아야 한다 → §9 R1, §11 CP-1.

### 5.5 악용 가능성 & 대응
| 악용/문제 | 설명 | 대응 |
|-----------|------|------|
| 속사 스팸 | 호흡을 무시하고 5 s 주기 난사 | 설계상 허용되는 "기본 전략". 호흡 이점(품질)이 부족하면 CP-1 적용. 플레이테스트로 점유율 측정 |

### 5.6 HUD 표현 요구사항
1. **월드 링(궁수 머리 위, 지름 1.2 m)**: 장전 중에는 회색-주사색 링이 D에서 0으로 **줄어든다**. 장전 완료 순간 "탁" 틱(사운드+햅틱) 후 금색(`#C9A227`) 호흡 링이 **0→10 s 동안 차오르고**, 10 s 지점에 금색 눈금(정점 마커), 이후 12→30 s에 걸쳐 회색(`#8A857C`)으로 식는다.
2. **수치(상단 좌측)**: "호흡 7.3s" 와 "효율 0.89" + 예상 다음 장전 "▶ 1.9s". 색에만 의존하지 않고 숫자를 병기(색약 대응).
3. **정점 도달 연출**: h=10.0 s에 링 번쩍 + 짧은 종소리(사운드 큐 `breath_peak`) + 미세 진동.
4. **발사 직후**: 장전 링이 D_next 길이에서 시작(링 전체 = 5 s 기준 비율). 호흡 효율 ≥0.9로 쐈다면 화살 궤적에 금색 꼬리 + "숨" 문구.
5. **상대 상태**: 상대 머리 위에는 "장전 중/준비" 두 상태만 표시(호흡량은 **비공개**). 상대가 정점 호흡 후 쏘면(E≥0.9) 금빛 발사 이펙트가 보여 곧 1.5 s 속사가 온다는 단서를 준다(심리전).
6. 추 미터 속도 변화는 막대 이동으로 자연스럽게 보이며 별도 설명 없음. 툴팁: 튜토리얼 첫 판에 호흡 링 설명 3컷.

### 6.1 데미지 표 (확정값 기반)

| 최대 HP | 100 |
| 몸통 | 25 |
| 머리 | 40 |

| 같은 화살 중복 | 1발 1회만 판정(관통 없음) |

| 킬에 필요한 명중 수 | 일반 | Perfect |

| 몸통만 | 4발 (100) | 4발 (124, 3발=93이라 4발 필요) |
| 혼합 예 | 머리 40 + 머리 40 + 몸통 25 = 105 (3발) | 머리 50 + 머리 50 = 100 (2발) |

- 최단 KO 시간: 속사 2발 = t≈10 s(5 s, 10 s 발사), 버스트 = t≈16.5 s(h=10 후 15 s, 16.5 s). 일반적 KO 기대: 4~6 명중 → 60~100 s.

### 6.2 히트박스 (제안, m 단위, 궁수 발밑 기준, 시각 높이 1.8 m)
| 부위 | 형태 | 크기 | 위치 | 우선순위 |
|------|------|------|------|---------|
| 머리 | 원 | 반지름 **0.25** (시각 머리 반지름 ≈0.12 + 관대 보정) | 중심 y=1.55 (정수리 1.80) | 1 (먼저 판정) |
| 몸통 | 사각형 | 폭 **0.60** × 높이 **1.30** (다리 포함) | y 0.0~1.30, x ±0.30 | 2 |

- 판정은 화살 **끝(촉)의 직전 스텝→현재 스텝 선분**으로 스윕 검사(터널링 방지; 최대 속도 22 m/s × 1/120 s = 0.18 m).
- 활과 소품은 판정 없음. 자기 화살은 자신을 맞히지 않음. 화살끼리 충돌 없음.
- 모바일 화면에서 1 m ≈ 34~40 px로 가정하면 머리 ≈ 17~20 px 반경: 터치 정밀도보다 **바람 보정 오차**가 지배적이 되도록 일부러 관대하게 설정.
- 명중 연출: 박힌 화살 3 s 후 페이드, 머리는 큰 흔들림 + 정지 프레임 0.06 s, HP바 즉시 감소 + 지연 잔상.

### 6.3 시간 종료 / 승패 규칙
1. HP ≤ 0 → 즉시 패배. 동시에 두 궁수 HP가 0이 되면(같은 물리 스텝 또는 호스트 판정 순서 동률) **무승부**.
2. t=120 s에 도달하면 신규 발사 금지. 비행 중 화살은 **최대 3.0 s 유예(Resolving)** 동안 착탄 유효.
3. 유예 종료 후 HP 높은 쪽 승, **동률은 무승부**(연장전 없음, 확장 후보 §10).
4. 같은 HP라도 데미지 총량/명중률 등은 결과 화면 표시만, 승패에 반영하지 않는다.

## 7. 봇 AI (LocalBotTransport)

### 7.1 알고리즘 (공통)
1. Ready 이후 난이도별 **조준 소요 시간**만큼 대기 후, 사거리·높이차·추정 풍속으로 탄도를 역산해 (θ, f)를 결정. θ는 22~58° 균등 선택(바람 대응을 위해 낮은 각도 선호 가중 옵션).
2. 추정 풍속 ŵ = 바람반영률 r × w(t_발사), **비행 중 바람 변화는 모른다**(§4.1의 실제 바람과 차이가 오차원).
3. 각도 오차 ε ~ N(0, σ²) 를 θ에 더하고, 힘에도 f_σ 오차를 더한다. p_equiv = ε/6°로 환산하여 \|p_equiv\| < 0.08이면 Perfect.
4. 호흡: Ready 후 h_target을 난이도 범위에서 균등 추출해 대기 후 발사(사이클마다 재추출). 호흡 공식은 플레이어와 동일.

### 7.2 난이도 3단계
| 난이도 | 각도 오차 σ | 힘 오차 σ_f | 바람 반영률 r | 호흡 대기 h 범위 | 조준 소요 | Perfect 확률(σ 기준) |
|--------|------------|-----------|--------------|----------------|----------|------------------|
| Easy (입문) | **3.5°** | 0.05 | 0.40 | 0~3 s (호흡 미활용) | 1.5~2.5 s | ≈ 11% |
| Normal (기본) | **2.0°** | 0.025 | **0.70** (확정) | **6~13 s** (확정) | 1.0~1.8 s | ≈ 19% |
| Hard (숙련) | **1.0°** | 0.012 | 0.90 | 8~12 s | 0.6~1.2 s | ≈ 37% |

- 목표 승률(평균 실력 플레이어 기준, 플레이테스트로 검증): Easy 85% / Normal 55% / Hard 25%.
- Normal의 6~13 s 호흡은 브리프 확정값이지만 §5.4에 따라 봇이 사격 수에서 손해를 본다(약 -35~45%). 봇 난이도 튜닝은 §9 체크리스트 #5 후 σ를 재조정한다.
- 봇은 "플레이어 상태"를 읽지 않는다(치팅 금지). 봇의 장전/호흡 상태는 플레이어와 동일 규칙, 동일 HUD 노출 수준.

## 8. 네트워크 대전 규칙

### 8.1 구조
- `IMatchTransport` 추상화: `LocalBotTransport`(기본), `LanTcpTransport`(호스트/참가). 상위 로직은 전송 방식을 모른다.
- **호스트 권위(authority)**: 경기시계, 장전/호흡(E, D_next) 계산, 히트 판정, HP, 승패는 호스트가 확정. 참가자는 입력(발사)만 보낸다.
- **결정론**: 바람 = f(seed, 경기시간), 화살 = 고정 스텝 적분(§4.1). 양쪽이 동일 입력으로 동일 궤적을 계산하므로 화살 위치는 매 프레임 전송하지 않는다.

### 8.2 메시지 (논리 정의)
| 메시지 | 방향 | 필드 |
|--------|------|------|
| MatchConfig | 호스트→참가 | rulesVersion, seed, distance(m), heightDiff(m), hostSide, startTime(호스트 시각) |
| ClockSync | 양방향 | pingId, 송신 시각, 수신 시각 (4회 평균 중앙값으로 오프셋 추정) |
| **ArrowFire** (참가→호스트) | 입력 | **playerId**, arrowId(플레이어별 증가), **angleDeg**(θ_aim, 오차 적용 전), **power**(f, 0~1), **p**(−1~1 추 오프셋), **fireTime**(경기시간 ms 정수), isAuto(선택, 자동 발사 여부) |
| ArrowAccepted | 호스트→전원 | playerId, arrowId, angleDeg, power, p, fireTime(보정 후), perfect, readyAfter(= D_next 반영 다음 Ready 시각) |
| HitResult | 호스트→전원 | arrowId, hitPart(None/Body/Head), damage, hpHost, hpGuest, impactTime |
| MatchEnd | 호스트→전원 | result(Win/Lose/Draw), reason(KO/Time/Forfeit), finalHp, stats |

### 8.3 검증 & 지연 처리
1. **쿨다운 검증**: 호스트는 `fireTime ≥ 직전 readyAt − 50 ms`인지 확인. 위반 시 거부하고 정확한 readyAt을 통지(참가자 UI 보정).
2. **시각 허용창**: 보정된 현재 경기시간 대비 `[−250 ms, +50 ms]` 밖의 fireTime은 현재 시각으로 클램프.
3. **고정 스텝 따라잡기**: 호스트는 도착이 늦은 ArrowFire를 받으면 fireTime부터 현재까지 화살을 **빨리 감기 시뮬레이션**하여 히트 판정에 반영. 참가자 화면은 예측 렌더링으로 즉시 화살을 띄우되 **HP 변화는 HitResult 수신 후**에만 적용.
4. **Perfect 판정 재계산**: 호스트가 \|p\| < 0.08을 직접 판정하며 클라이언트 보고값을 신뢰하지 않는다. p 범위 외 값은 [−1,1]로 클램프, angleDeg는 [−10°,85°]로 클램프, power는 [0,1].
5. **자동 발사**: 참가자 클라이언트가 3 s 타임아웃을 직접 판정하고 ArrowFire에 `isAuto=true`를 담아 전송한다(§8.2의 선택 필드, 프로그램에 추가 권고). 호스트는 `isAuto`인 발사를 Perfect 불가로 처리한다.
6. 동시 발사/동시 KO는 호스트가 impactTime 오름차순으로 처리; 동일 스텝이면 무승부(§6.3).

### 8.4 연결 이상
| 상황 | 처리 |
|------|------|
| 핑 > 250 ms | 경고 아이콘. 호스트 허용창 확대 안 함(공정성) |
| 참가자 응답 없음 5 s | "재연결 중" 표시, 경기시계는 계속 흐름 |
| 10 s 초과 | 기권 처리 → 상대 승, reason=Forfeit |
| 호스트 이탈 | 참가자 화면에 "상대 연결 끊김", 무효 경기(전적 미반영) |
| rulesVersion 불일치 | 입장 거부 |

## 11. 변경 제안 (확정 수치 변경 희망 및 추가 확정 필요 사항)

> 본문은 모두 브리프 확정값으로 작성했다. 아래는 플레이테스트 후 채택을 검토할 제안이며, **채택 전까지 구현에 반영하지 않는다.**

### CP-1 호흡의 품질 보상 강화 (R1 대응) — 권고안
- **문제**: 순수 발사 수는 h=0 속사가 최대(§5.4). 호흡은 추 주기 +30%만으로 속사 대비 -39%의 발사 수를 상쇄해야 한다. 대기형이 동률이 되려면 명중률 1.4~1.65배가 필요.
- **안 A (권고)**: 호흡 효율이 추 **진폭**도 줄인다 — 각도 오차 = p × 6° × (1 − 0.3·E). E=1이면 최대 ±4.2°. 기존 "호흡 = 안정"이라는 테마와 일치. 다른 확정 수치는 불변.
- **안 B**: Perfect 폭을 0.08 + 0.06·E로 확대(E=1에서 0.14 → 창 약 49 ms).
- 안 A 먼저 시험, 호흡 사용률(체크리스트 #1)이 40% 미만이면 B 병행.

### CP-2 Perfect 판정 창 확대 (R2 대응)
- 현재 \|p\| < 0.08 은 사인파 중앙 통과 시 28 ms로 매우 좁다. 모바일 터치 지연 편차에서 체감 달성률이 5% 미만일 가능성.
- 제안: 임계값 0.08 → **0.12**(창 약 42 ms, 무작위 탭 7.7%) **또는** 추 파형을 사인에서 **삼각파**로 변경(0.08 유지 시 창 약 44 ms). 파형 변경이 시각적으로 덜 어색한 쪽을 아트와 상의.

### CP-3 문서에서 새로 추가한 확정 후보 규칙 (브리프 미정의 → 프로그램이 구현 시 따를 것)
1. 매치 시작 시 양측 D=5.0 s 장전 (§5.2).
2. 조준 각도 범위 −10°~85°, 힘 매핑 40 px 데드존~360 px 선형 (§3.2).
3. 추: 사인파·끝점 시작·0.15 s 입력 유예·자동 발사는 Perfect 불가 (§3.3).
4. 시간 종료 후 3.0 s 착탄 유예(Resolving), 동률 무승부, 연장전 없음 (§6.3).
5. 히트박스 제안: 머리 r 0.25 m, 몸통 0.60×1.30 m (§6.2). 플레이 후 조정 가능.
6. Perfect 데미지 반올림 31 / 50 (§6.1).
7. ArrowFire에 `isAuto` 필드 1개 추가 권고 (§8.3-5).

### CP-4 HUD 보강 (수치 변경 아님)
- 현재 사거리(m)와 높이차(m)를 상단에 상시 표시(R4 대응). 조준 가이드(점 3개)는 그대로 유지.
- 호흡 링에 정점(10 s) 눈금 + "예상 다음 장전" 수치(§5.6).

### CP-5 (보류) 기본 딜레이 B 변경은 제안하지 않음
- B=6.0, 최소 1.8 s로 올려도 속사 대비 발사 수 비율은 -39% → -33% 수준으로 크게 개선되지 않는다. 브리프 확정값 B=5.0 유지, CP-1/CP-2로 해결 시도 후 재평가.
