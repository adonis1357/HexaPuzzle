# 「활」(Hwal) 아트 비주얼 사양서

> 작성: 아트 디렉터 / 수신: programmer / 기준: `00_프로젝트_브리프.md` §3 (확정). 본 문서는 **코드 수정 없이 사양만** 기술한다.
> 단위 규칙: **m = Unity 월드 유닛(1u = 1m)**, **px = 1080×1920 기준 해상도 픽셀**. 각도는 도(°), 시간은 초(s).
> 모든 스프라이트는 런타임 `Texture2D`(FilterMode.Bilinear, 엣지 AA는 `Mathf.Clamp01` 페이드) → `Sprite.Create`. 외부 에셋 없음.

## 1. 아트 컨셉 & 팔레트

**컨셉 문장**: 번진 한지 위에 먹 한 획으로 그어낸 두 궁수의 결투 — 바람은 붓이 스친 자국이고, 명중은 먹이 튀는 순간이다.

**무드 키워드**: 여백 / 건필(마른 붓) / 번짐 / 정적 속의 긴장 / 절제된 붉음 / 금박의 한 점

**디자인 원칙**
1. **실루엣 우선**: 궁수·활·화살은 단색 면. 디테일은 팀색 포인트 1~2곳뿐.
2. **여백이 가독성**: 배경은 명도 0.85 이상 유지, 화살(가는 선)이 항상 대비되도록 먹/팀색 사용.
3. **금박은 보상 전용**: 금색은 호흡 링·Perfect에만 쓴다 (다른 곳 사용 금지 → 의미 오염 방지).
4. **주사=나, 쪽빛=적**: 팀색은 HP바·머리띠·허리띠·화살 깃·궤적에만 적용.

## 2. 화면 레이아웃 (세로 1080×1920)

### 2.1 월드 카메라
- Canvas: Screen Space - Overlay, CanvasScaler `Scale With Screen Size`, 참조 1080×1920, Match = 0.5. HUD는 카메라 흔들림 영향 없음.
- 카메라: Orthographic, 배경 Solid `#F3EAD3`.
- **지면 기준선(world y=0) = 화면 하단에서 700px (위에서 1220px)** — 상단 HUD 260px, 하단 조작/게이지 존 700px 확보.
- 경기 시작 시 1회 계산 (경기 중 줌 변화 없음):
  - 궁수 간 거리 D (16~24m), 궁수 x = ±D/2 (중점 x=0).
  - `orthoSize = (D + 4) / 1.125` → D=16: 17.8 / D=20: 21.3 / D=24: 24.9. (가로폭 = 1.125×size, 양쪽 여백 각 2m)
  - `ppm(px/m) = 1920 / (2·orthoSize)` → D=16: 54 / D=24: 38.6.
  - 카메라 y = `(960 − 700) / ppm` (지면 y=0이 화면 아래 700px에 오도록). x = 0.
- 높이차(±1.5m): 지면 기준(y=0)은 두 궁수 발 높이의 평균. 플레이어 발 y = −diff/2, 상대 발 y = +diff/2 (부호는 seed).
- 화살 최대 고도(v=22, 45°) ≈ 12.3m: D=24 기준 지면 위 화면 가용 31.6m, D=16 기준 22.6m → 화면 이탈 없음. 이탈 시(약한 가능성) 화살 위치에 **위쪽 화면 가장자리 삼각 마커**(가로 28px, 먹 알파 0.6, x 추적) 표시 — P1.

### 2.4 바람 인디케이터 (TopCenter, 360×100)
- 배경: 없음(여백). 중앙 기준선 세로 6×40px 먹 알파 0.4.
- **화살표**: 가로 막대(먹, 높이 8px) 길이 `Lw = 20 + 120 × min(|w|/7, 1)` px → 20~140px, 중심에서 풍향 쪽으로 뻗음. 끝에 삼각형 머리 28×28px(풍향 방향).
- 표시값 평활: 길이는 `Lerp(cur, target, 1 − e^(−10·dt))`. 풍향 반전 시 머리 scaleX 부호 전환 0.12s `EaseOutCubic`.
- 숫자: 막대 아래 `바람 3.2 m/s` 폰트 38 먹 (순풍 방향 문자 `→/←`는 화살표가 이미 있으므로 생략). 풍속 5 이상이면 숫자 색 주사.
- P1 보강: 월드 지면 중앙(x=0)에 깃대 3m + 천 5분할(LineRenderer 폭 0.25m) 사인 파동 `y += 0.12·sin(2π(1.6t − i·0.35))·(|w|/7)`, 풍향 쪽으로 기울기 `15° + 55°·min(|w|/7,1)`.

### 2.5 호흡 링 (지름 240px, 두께 24px)
- 스프라이트: 256×256 환형(외반경 126, 내반경 100 texel, AA 1texel) → `Image.type=Filled, FillMethod=Radial360, FillOrigin=Top, Clockwise`.
- 뒤 트랙: 같은 스프라이트 먹 알파 0.15. 눈금: 12시(10초 지점) 6×28px 먹 알파 0.5, 6시(5초) 4×20px.
- 색 전이 타임라인은 §4.5.

### 2.6 정확도 추 미터 (BottomCenter, 바 800×56)
- 트랙: 800×56 직사각형, 먹 알파 0.12 면 + 먹 3px 테두리(모서리 지터 ±2px로 붓 느낌). 추가 활성화 전에는 알파 0.25 고스트로만 표시.
- 추 이동 범위: x = `p × 400` px (p∈[−1,1]). 위상: p = `sin(2π·t/T)`, **T = 1.1 × (1+0.3E)**.
- **Perfect 존**: |p|<0.08 → 폭 `0.16 × 400 = 64px`, 높이 56px, 금박 알파 0.85 + 먹 2px 테두리, 중앙. Good 존(|p|<0.4, 320px) 은 금박 알파 0.15 띠.
- 추(錘): 원 지름 44px 먹 + 위로 뻗는 실 5×72px(바 위로 56px 돌출). |p|<0.08일 때 금박으로 전환 + 스케일 1.15.
- 잔상: 추 위치 t−0.03/−0.06/−0.09s 지점에 알파 0.35/0.2/0.1 복제 3개.
- 탭 시: 추 0.25s 정지(`HitStop` 아님, 단순 정지) + 판정 라벨(§2.3 일시 메시지: `완벽!`/`좋음`/`보통`).
- 3초 자동발사 카운트: 바 끝 우측에 얇은 먹 선 800px가 3s에 걸쳐 줄어듦(높이 4px, 바 아래 8px).

### 2.7 조준 표시 (드래그 중)
- 드래그 시작점에 원 마커 지름 28px (먹 알파 0.5). 최대 당김 반경 **300px = 힘 1.0**, 데드존 40px(그 이하 해제 시 취소).

## 3. 오브젝트별 도형 사양 (월드 m)

공통: 궁수 파트 스프라이트는 **흰색 텍스처 + `SpriteRenderer.color`로 착색** (피격 백색 플래시를 위해). 사각형 = 16×16 흰색(1px 투명 AA 테두리), ppu 16 → 스케일로 크기 지정.

### 3.1 궁수 실루엣 (총 높이 1.91m, 오른쪽을 바라보는 기준 / 상대는 root.scale.x = −1)
루트 pivot = 발 중앙(지면 접촉점). 로컬 좌표(m).

| 파트 | 도형 | 크기 | 피벗 | 로컬 위치 | 색 |
|------|------|------|------|-----------|----|
| 다리 앞 | 사각 | 0.20 × 0.80 | 상단 중앙 | (+0.10, 0.80) | 먹, 회전 +6° |
| 다리 뒤 | 사각 | 0.20 × 0.80 | 상단 중앙 | (−0.10, 0.80) | 농먹 `#0E0C0B`, 회전 −6° |
| 몸통 | 사각 | 0.50 × 0.66 | 하단 중앙 | (0, 0.80) | 먹 |
| 허리띠 | 사각 | 0.52 × 0.07 | 중앙 | (0, 1.10) | 팀색 |

- 어깨 pivot S = (0.05, 1.38). 에임 방향 단위벡터 `dir = (cosθ, sinθ)` (θ = 발사각, 상대는 root 미러로 자동).
- **판정 박스 제안(물리 담당 참고)**: 머리 원 반지름 **0.30** (시각 0.21보다 관대), 몸통 박스 x ±0.30 × y 0~1.48. 머리 우선 판정.
- 그림자: 발밑 타원 0.9×0.18m, 먹 알파 0.25.

### 3.2 활 (LineRenderer)
- 그립 G = S + dir × 0.62 (활 든 팔 끝). 호의 중심 C = G − dir × R.
- 호: θ_rel ∈ [−α, +α], 점 `P_i = C + R·(rot(dir, θ_rel))`, **샘플 24점**.
  - 이완: R = **0.85**, α = **55°** (활 높이 ≈ 1.39m)
  - 만작(당김 d=1): R = **0.72**, α = **70°** (`R, α = Lerp(이완, 만작, d)`; d = 힘 0~1)
- 폭: 중앙 **0.07m** → 끝 **0.03m** (`widthCurve`: 0→0.03, 0.5→0.07, 1→0.03), 색 먹, `numCapVertices=4`, `useWorldSpace=true`.
- 그립 장식: 팀색 사각 0.08×0.14m (G 위치, 활 회전 정렬).
- **시위**: LineRenderer 3점 `(tipA, nock, tipB)`, 폭 **0.04m**(1.5~2px 보장), 색 먹 알파 0.7.
  - `nock = G − dir × (0.15 + 0.60 × d)` (d=힘; 최소 0.15m).
  - 시위 당기는 손 = nock.

### 3.3 화살
- 스프라이트 128×16 텍스처, **ppu 128 → 길이 1.0m**, 높이 0.125m. **피벗 = 촉 끝 (1.0, 0.5)** (물리 위치=촉 끝).
- 구성(texel): 샤프트 x 14~112, 두께 **6px(0.047m)** 먹 / 촉 삼각형 x 112~128, 높이 14px(0.11m) 먹 / 깃(fletching) x 0~28, 위·아래 평행사변형 각 5px 돌출 팀색 / 노크 홈 1px 생략.
- 가시성 확대: 실제 판정은 점(촉 끝)이지만 시각 두께를 의도적으로 키움 (§9-2).
- 회전: 매 프레임 `angle = atan2(vy, vx)` (속도 방향 정렬). 착탄 후 고정.
- 꽂힘: 착탄 시 몸에 0.35m 박힘(촉 끝 기준 역방향 오프셋), 유지 3s → 0.5s 알파 페이드 → Destroy. 최대 동시 꽂힌 화살 12개 (초과 시 가장 오래된 것부터 페이드).

### 3.4 지면 (잉크 붓터치)
베이크 방식: 경기 시작 시 `Texture2D 2048×512` 1회 생성(ppu 51.2 → 월드 40m × 10m), SpriteRenderer.
1. **윤곽 H(x)**: 두 궁수 발 높이 yP, yE를 `smoothstep`(코사인 보간)으로 연결 + 각 궁수 주변 ±0.8m 평탄 고원. 잡음 `0.18·sin(0.9x+φ1) + 0.10·sin(2.3x+φ2)` (φ는 seed).
2. 픽셀 (px,py): `y_m = py/51.2 − 지면깊이오프셋`, `inside = y_m < H(x)`. 윗가장자리 AA 1texel.
3. **세로 번짐 그라디언트**: 윗선에서 아래로 깊이 d(m): 알파 `a = 0.92 (d<0.3) → 0.55 (d=1.5) → 0 (d=6)` 선형 구간 보간. 색 = 먹 → 깊을수록 연먹 `#4A4540` 쪽으로 Lerp.

## 4. 애니메이션 사양

### 4.1 활 당기기 (조준 중)
- 드래그 입력 각도→`θ_target`(조준 발사각 = 드래그 반대 방향), `θ += (θ_target − θ) × (1 − e^(−20dt))`.
- 힘 d = 길이/300 (0~1)로 활 R/α, nock 거리(§3.2)가 연속 변화. 시위 당기는 팔은 nock에 손 고정.
- 상체 기울임: 몸통(+머리) 루트 회전 `−4° × d` (표적 반대쪽으로 젖힘), `EaseOutCubic` 0.15s 추종.
- **홀드 떨림(추 미터 구간)**: 활 전체에 위치 오프셋 진폭 `0.01m → 0.03m` (경과 0→2.5s 선형), 주파수 14Hz, 방향 y 위주 (시각 전용).

### 4.2 발사 반동 (총 0.30s)
| 시간(s) | 동작 |
|---------|------|
| 0.00 | 화살 생성(노크 위치), 시위 스냅 시작 |
| 0.00~0.25 | 시위 노크 변위 `x = −nockDist·e^(−t/0.06)·cos(2π·18t)` (감쇠 진동, 시위 선만) |
| 0.00~0.18 | 활 회전 −6° → 0, `EaseOutBack` (활 앞으로 튐) |
| 0.00~0.20 | 상체 −3° 반동 후 복귀 `EaseOutCubic` |
| 0.00~0.12 | 시위 당기던 팔 뒤로 0.08m 밀렸다 복귀 |
| 0.00 | 발사 먼지(§5) + 힘>0.7이면 카메라 흔들림 4px |

### 4.3 피격 (몸통 / 머리)
| 항목 | 몸통(25) | 머리(40) |
|------|---------|---------|
| 흔들림 진폭 (루트 x, 화살 반대방향) | **0.12m** | **0.20m** |
| 지속 | 0.28s | 0.40s |
| 주파수 / 감쇠 | 22Hz, `e^(−t/0.09)` | 22Hz, `e^(−t/0.12)` |
| 백색 플래시 | `#FFFFFF`, t=0에서 100% → 0.14s `EaseOutCubic`로 원색 복귀, 0.06s 깜빡임 1회 추가 | 동일 + 총 0.22s |
| 몸 틸트 | 반대방향 +6° → 0 (0.25s, EaseOutElastic) | +11° → 0 (0.4s) |
| 잉크 점 | 먹 점 6개 | 먹 점 14 + 스플래시(§5) |
- 플래시 구현: 파트 SpriteRenderer.color를 `Lerp(원색, white, f)` (흰 텍스처 착색 방식이라 완전한 백색 가능).

### 4.4 사망 (쓰러짐, 1.4s)
1. t=0: 피격 플래시 + 흔들림은 위와 동일(머리 규격 사용).
2. 0~0.9s: 루트가 발 피벗 기준으로 **화살 진행 방향으로 0° → 88° 회전**, `EaseInQuad`(가속 낙하). 0.9~1.2s: 바닥 바운스 `88° → 84° → 88°` (진폭 4°).
3. 활: 손에서 분리, 부모 해제 후 간이 중력(월드 y −9.8) + 회전 180°/s로 낙하, 지면 착지 시 정지(0.8s 내).
4. 0~1.0s: 몸 색 먹 → 회색먹 `#8A857C` 선형. 팀색 띠는 알파 0.4로.
5. 착지 순간 먹 웅덩이 타원 0.2×0.05m → 1.1×0.18m (0.5s, `EaseOutCubic`), 알파 0.4.
6. 카메라 흔들림 22px (§5). 슬로모 시각 전용 0.4× 0.6s (결과 연출 진입 전).
7. 이후 1.2s 대기 → 결과 화면(§6.3).

### 4.5 호흡 링 색 전이 타임라인
h = 초과 대기 시간(s), D = 현재 장전 딜레이(s), E = 효율.
| 구간 | 조건 | 채움 | 색 | 기타 |
|------|------|------|----|------|
| ① 장전 중 | 발사 후 t∈[0,D] | **1→0 감소**(시계 반대로 줄어듦) | 회색먹 `#8A857C` 알파 0.85 | 중앙 남은 초 `3.2` 폰트 56 회색먹 |
| ② 준비 | t=D (h=0) | 0 | 금박D `#8E741A` | 순간 펄스: 링 스케일 1→1.12→1 (0.15s, EaseOutBack), 한지L 섬광 1프레임, 텍스트 `준비` |
| ③ 상승 | 0<h≤10 | **h/10 증가**(시계 방향) | `h:0→7`: 금박D→금박, `h:7→10`: 금박→금박L `#E8CB5A` | 중앙 `h`초 + `효율 E%` |
| ④ 정점 | h∈[9.6,10.4] | 1.0 | 금박L `#F0D775` | 진입 시 외곽 글로우 링 스케일 1→1.5, 알파 0.8→0 (0.45s); 금빛 점 6개 방사(§5); 이후 0.8Hz 펄스 ±4% 스케일; 텍스트 `MAX` |
| ⑤ 식음 | h>10 | **E(h)로 감소** (h=20→0.74, 30→0.41) | 금박L→회색먹 선형, `t=(h−10)/20` | 펄스 정지, 텍스트 효율% 회색 |
| 발사 시 | — | — | — | 링 전체 알파 0.4로 0.1s 페이드 후 ①로 재시작(채움 1.0) |
- 호흡 효율 E가 높을수록 추 미터 속도도 변하므로 추 미터 테두리 색에 약하게 반영: 테두리 `Lerp(먹, 금박, E)` (P1).

## 9. 변경 제안 (브리프 대비 이견 / 확인 요청)

1. **카메라 줌 고정 방식**: 브리프는 사거리 16~24m. 고정 줌 시 D=16에서 궁수가 너무 작거나 D=24에서 화면 밖. **제안: 경기 시작 시 D로 1회 줌 결정** (`orthoSize=(D+4)/1.125`, §2.1). 경기 중 줌 변화 없음(조준 일관성). 근거: 해상도 1080px 폭에 24m 수용 시 38.6px/m로 궁수 키 74px, 가독성 한계선.
2. **시각 스케일 과장**: 화살 시각 두께 0.047m(약 2px)와 길이 1.0m는 실제 판정(점)보다 크다. 헤드 판정 반지름 0.30m(시각 0.21m)도 관대하게 제안 — 모바일 정밀도 보정이며 **물리/기획 담당의 판정 박스 확정 필요**.
3. **히트스톱은 시각 전용**: 결정론(고정 스텝 적분, 호스트 권위) 때문에 `Time.timeScale=0`을 시뮬레이션에 적용하면 LAN 양측이 어긋난다. 80ms 정지/슬로모는 **표시 계층(파티클/카메라/애니메이터 deltaTime)에만 적용**하고 시뮬 틱은 계속 진행해 주세요.
4. **추 미터 시작 위상 / Perfect 폭**: 브리프의 |p|<0.08은 800px 바에서 64px(화면폭 6%)로 좁다. 손을 뗀 직후 p=0(중앙)으로 시작하면 우연한 Perfect가 쉽게 나오므로 **시작 위상을 p=−1(좌측 끝)로** 제안. Perfect 폭 자체는 기획 밸런스 사항이므로 유지하되, 시각 존 폭만 판정과 동일하게 유지(거짓 표시 금지). 기획 확인 요청.
5. **호흡 링 식음 표현**: 브리프 "서서히 회색으로 식는다"를 **채움량을 E(h)로 감소**(h=20→74%)+색 전이로 이중 표현. 단순 색만 바꾸는 것보다 손해 직관이 큼. 승인 시 확정.
6. **금박 변형 색 사용**: 금박L `#F0D775` 등은 팔레트 명도 변형(허용 범위)이며 새 색상이 아님. 단 금박은 호흡/Perfect 전용으로 제한.
7. **하단 조작 존**: 한 손 엄지 가림을 줄이기 위해 호흡 링을 중앙 하단 (y 400px), 추 미터를 최하단 (y 150px)에 배치. 추 미터는 손을 뗀 후에만 활성이라 가림 문제 없음. 조작 영역은 전 화면 허용 유지.
